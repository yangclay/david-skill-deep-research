# 深度调研中的"真实差距分析"模式

> 来源于：2026-05-14 Claude Code skill creator 调研

## 模式描述

Clay 的调研问题往往不是"X 是什么"，而是**"X 和我们已有的有什么本质区别"**。

典型的追问链：
1. "调研一下 X" → 初始搜索
2. "有没有现成成熟的？" → 搜索现有方案
3. "实际有什么惊艳的提升？" → 要求区分"真正有价值的"vs"表面功能"
4. "有什么区别？" → 要求和现有能力做对比

## 应对方式

在 Step 0（问题分解）时就应加入一个子问题：**"现有方案已经能做什么？X 的真正增量是什么？"**

不要等到 Clay 追问才做对比分析。调研报告的"核心结论"部分，第一条就应该是：
- **X 的真正价值是什么**（不是功能列表，而是解决的痛点）
- **和现有方案的差距在哪里**（不是"X 有 A/B/C"，而是"X 能做而现有方案做不到的"）

## 反面教材

本次调研前半段堆了很多功能对比表，但没有提炼出核心洞察。直到 Clay 追问"实际有什么惊艳的提升"，才总结出：
> "创建 skill 不是问题，衡量和迭代 skill 才是真正差距。"

这句话应该在第一轮报告里就有。
