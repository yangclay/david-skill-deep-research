# 报告输出规范（Reporting）

## 报告结构

### 必需部分
1. **核心结论**（3-5 条，带可信度 A/B/C/D）
2. **调研过程**（子问题、关键来源引用、**原查询→变体对照表**）
3. **来源列表**（每行含**可点击 URL**、类型、可信度）——**缺 URL 列 = 报告不达标**，来源不可追溯
4. **矛盾记录**（不同来源说法差异、如何判断）
5. **Gotcha 检测**（显式引用 G-001/G-012/G-013/G-014/G-017 状态）
6. **独立验证**（Step 6 确定性复核结果，非作者自评）

### 可选部分
- 数据对比表、时间线、下一步行动建议

## 报告质量 Checklist

- [ ] 问题已分解为 2-5 个子问题
- [ ] 每个子问题有查询变体，且报告含"原查询→变体"对照表（缺对照表判不达标）
- [ ] 核心子问题有 ≥ 2 个独立来源
- [ ] 已执行相关性过滤（Jina rerank + 规则 filter）
- [ ] 重要结论标注可信度等级（A/B/C/D）
- [ ] 动态事实标注了时间戳
- [ ] 来源列表每行有可点击 URL（缺 URL 判不达标）
- [ ] 已完成 Step 6 独立验证（确定性复核，非 LLM 自评）
- [ ] 入库：仅用户明确指定时写 `raw/research/` 并 sync，否则不写盘、只在聊天给结论
- [ ] 聊天中给了核心结论（+ 若入库的文件路径）

## 交付规范（2026-08-24 反转：对话优先，文件是升级动作）

1. **默认交付 = 对话框**：完整调研结果直接发聊天——核心结论（带可信度）+ 来源列表（可点击 URL）+ 矛盾记录 + Gotcha 摘要，按报告结构组织但压缩过程细节。对话版标准：Clay 不看文件就能做决策
2. **文件报告 = 用户拍板后的升级动作**：Clay 看完对话版说"有价值/存一份/出报告"才写 `raw/research/主题-YYYY-MM-DD.md` 并 sync。**判断权在用户，agent 不预判价值**
3. 文件版 = 实质内容 + 全过程（子问题拆解、原查询→变体对照表、Gotcha 全表）——两版分工：对话版管决策，文件版管回查
4. 对话版超长（Telegram 4096 字符）→ 分条发送，先结论后来源
5. 有需要决策的点，明确指出并给推荐
6. 教训沉淀照旧 `hindsight_retain`

## 文件名规范

**格式**：`主题关键词-YYYY-MM-DD.md`
**禁止**：`调研报告.md`（无主题）、`2026-08-13-主题.md`（日期在前）

## Gotcha 检测章节

每次调研完成后，报告末尾添加：

```markdown
## Gotcha 检测

| Gotcha ID | 标题 | 状态 | 说明 |
|-----------|------|------|------|
| G-001 | 伪独立来源 | ✅ 显式引用 | 已追溯引用链 |
| G-012 | SEO 内容农场 | ⚠️ 部分生效 | 已标注来源类型 |
| G-013 | 时效性过时 | ✅ 显式引用 | 已检查发布日期 |
| G-014 | Citation 支撑失败 | ✅ 显式引用 | 已抓取原文验证 |
| G-017 | 冲突静默 | ⚠️ 部分生效 | 已标注冲突 |
```

**状态说明**：
- `✅ 显式引用`：已检查并执行
- `⚠️ 部分生效`：部分符合
- `❌ 未生效`：未执行
- 不适用 → `N/A`
